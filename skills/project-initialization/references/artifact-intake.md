# Artifact intake

Use this reference when source material spans multiple files, formats, or
authorities.

## Inventory

For each artifact record path, type, date/version if available, likely owner,
scope, dependencies, and whether a more authoritative source supersedes it. Do
not infer authority from filename alone.

## Extraction

Extract decisions and requirements with the smallest stable locator available.
Separate explicit statements from interpretation. For tables or diagrams,
capture semantics and relationships rather than formatting.

## Conflict resolution

Prefer an explicit approved decision over an older proposal, executable schema
for current behavior over stale prose, and the human product owner for business
truth. Do not silently resolve a conflict between intent and implementation;
classify its impact and request a decision when material.

## Missing artifacts

Request an artifact only when it can resolve a real blocker or materially reduce
risk. An absent conventional document is not itself a problem.
