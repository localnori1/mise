# UX and screen readiness

Use this for a user-facing workflow or material interaction change.

## Determine the experience

- Actors, goals, entry points, prerequisites, and permissions
- Steps and state transitions; avoid a new page when modal, drawer, inline action,
  or existing screen is more coherent
- Required content, information hierarchy, primary and secondary actions
- Inputs, validation, destructive confirmations, cancellation, and recovery
- Loading, empty, error, partial, offline/interrupted, success, and return states
- Keyboard, focus, semantics, contrast, labels, announcements, and reduced motion
- Small-screen behavior, touch targets, content reflow, and localization pressure
- Analytics or support signals only when they answer a real product question

## Readiness output

Summarize screens/components, flow, state model, permissions, accessibility,
responsive behavior, missing rules, ambiguities, risks, and decisions owned by
the human. Use a compact table or flow only when it improves comprehension.
